# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

The current prototype uses a plud-inspired 640px editorial shell for Zahirul Iman's portfolio. Preserve the Geist typography, local project assets, direct animated light/dark toggle, restrained surfaces, and Zahirul's positioning as a Product Designer & Digital Product Builder unless the user explicitly requests a redesign.

Keep the menu and light/dark controls together as one compact top-right control rail. The menu control must retain a visible Menu/Close label except on very narrow phones, use a real CSS morphing glyph rather than the unreliable stroked-SVG mask, and anchor the full-screen menu reveal to its position. Theme changes should use a restrained circular View Transition emitted from the theme control when supported, with an immediate reduced-motion fallback.

Use the supplied monochrome creative-tools illustration as the main hero visual, directly above the opening introduction.

Once the main hero illustration has fully left above the viewport, reveal a slim fixed fabric-style ribbon tab aligned to the left edge of the 640px content column. Use a downward arrow point rather than an inverted swallow-tail cut, keep the fabric surface free of inset border or stitch lines, and let its entrance settle with a short damped fabric-like motion. The ribbon contains the locally generated transparent head-only portrait derived from the main creative-tools illustration, stays beneath the menu layer, and retracts when the hero illustration returns. Clicking it plays the local one-shot transparent animated WebP in which the head lowers, the camera portrait rises and recoils, then the normal portrait returns; the normal and animated states must retain the same perceived head scale. Synchronize one full-viewport white camera flash to the recoil. Do not strobe or repeat automatically; reduced-motion users receive only the static camera portrait swap without the flash.

Motion should feel quiet, precise, layered, and editorial. Use one choreographed hero entrance, then viewport-triggered motion only for meaningful chapter arrivals: staggered copy layers, media reveals, true list staggering, the activity grid, the featured SesiFoto card, and the chat shell. Let these entrances replay smoothly after an element fully leaves and later re-enters the viewport. Keep continuous motion extremely subtle and limited to the hero illustration plus contextual loops such as typing and hover-triggered fire. Avoid generic whole-section fade-and-rise repetition, continuous parallax, bounce, elastic easing, or blocking interactions. Fully disable decorative motion for reduced-motion preferences.
